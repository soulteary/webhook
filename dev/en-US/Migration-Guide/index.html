    Migration Guide

    This guide helps you migrate from previous versions of Webhook or from the original webhook project to this fork.

    Table of Contents

    1. Migrating from Original Webhook
    2. Upgrading Between Versions
    3. Breaking Changes
    4. Configuration Migration

    Migrating from Original Webhook

    This fork (soulteary/webhook) is based on the original webhook project (adnanh/webhook) with significant improvements in security, performance, and features.

    Key Differences

    1. Security Enhancements:
    2. Command path whitelisting
    3. Argument validation and limits
    4. Strict mode for command injection prevention

    5. Improved logging with sanitization

    6. Performance Improvements:

    7. Better concurrency control
    8. Configurable timeouts
    9. Rate limiting support

    10. Optimized request handling

    11. New Features:

    12. Prometheus metrics endpoint
    13. Health check endpoint
    14. Enhanced error handling

    15. Better logging and debugging

    16. Configuration Compatibility:

    17. Compatibility with original hook definitions is a maintained target, not a blanket guarantee across major versions
    18. Additional security and performance parameters
    19. The default compat profile preserves historical runtime defaults; secure is an explicit, stricter opt-in

    Compatibility Contract

    Hook JSON/YAML compatibility is tested and regressions are treated as bugs. Runtime behavior, HTTP error contracts, CLI options, defaults, and release asset names may still change in a major release. Review every intervening release note and validate in staging; do not infer upgrade safety only from hook-schema compatibility.

    Migration Steps

    1. Backup Current Configuration: 

      cp hooks.json hooks.json.backup
cp /path/to/webhook /path/to/webhook.backup

    2. Download New Version: 

      # Download a versioned release archive
VERSION=7.1.0
wget "https://github.com/soulteary/webhook/releases/download/${VERSION}/webhook_${VERSION}_linux_amd64.tar.gz"
tar -xzf "webhook_${VERSION}_linux_amd64.tar.gz"

# Or use Docker
docker pull soulteary/webhook:latest

    3. Test Configuration: 

      # Validate configuration
./webhook -validate-config -hooks hooks.json

    4. Gradual Migration:

    5. Start with a test environment
    6. Run both versions in parallel if possible
    7. Monitor for issues

    8. Gradually migrate production

    9. Update Configuration (Optional):

    10. Add security parameters (recommended)
    11. Configure rate limiting
    12. Set up monitoring endpoints

    Recommended Security Updates

    After migration, enhance security:

    # Add command path whitelist
webhook \
  -allowed-command-paths="/usr/bin,/opt/scripts" \
  -strict-mode \
  -hooks hooks.json

# Or via environment variables
export ALLOWED_COMMAND_PATHS="/usr/bin,/opt/scripts"
export STRICT_MODE=true
webhook -hooks hooks.json

    Upgrading Between Versions

    General Upgrade Process

    1. Review Release Notes:
    2. Check for breaking changes
    3. Review new features

    4. Note deprecated features

    5. Backup: 

      # Backup configuration
cp hooks.json hooks.json.backup

# Backup binary
cp /usr/local/bin/webhook /usr/local/bin/webhook.backup

    6. Test in Staging:

    7. Deploy new version to staging
    8. Run full test suite

    9. Verify all hooks work correctly

    10. Update: 

      # Download new version
VERSION=X.X.X
wget "https://github.com/soulteary/webhook/releases/download/${VERSION}/webhook_${VERSION}_linux_amd64.tar.gz"
tar -xzf "webhook_${VERSION}_linux_amd64.tar.gz"

# Replace binary
sudo install -m 0755 webhook /usr/local/bin/webhook

    11. Restart Service: 

      # systemd
sudo systemctl restart webhook

# Docker
docker restart webhook-container

    12. Verify: 

      # Check version
webhook -version

# Check health
curl http://localhost:9000/health

# Test a hook
curl http://localhost:9000/hooks/test-hook

    Version-Specific Upgrades

    Upgrading to 3.6.x

    New Features: - Prometheus metrics endpoint - Health check endpoint - Enhanced error responses - Improved logging

    Configuration Changes: - No breaking changes - Optional: Add security parameters - Optional: Configure rate limiting

    Migration: 

    # No configuration changes required
# Optional: Add security settings
webhook \
  -allowed-command-paths="/usr/bin,/opt/scripts" \
  -strict-mode \
  -hooks hooks.json

    Upgrading to 3.5.x

    New Features: - Rate limiting support - Enhanced timeout configuration - Improved concurrency control

    Configuration Changes: - New optional parameters for rate limiting - New timeout parameters

    Migration: 

    # Existing configuration works as-is
# Optional: Enable rate limiting
webhook \
  -rate-limit-enabled \
  -rate-limit-rps=100 \
  -rate-limit-burst=20 \
  -hooks hooks.json

    Breaking Changes

    Configuration File Format

    Status: Hook-definition compatibility is a project target, but it is not a substitute for reviewing major-version changes.

    Existing adnanh/webhook definitions should normally validate without modification under the compat profile. Validate the exact configuration and exercise its trigger and error paths before upgrading production.

    Command-Line Arguments

    Status: Backward compatible with additions.

    All original command-line arguments are supported. New arguments are optional and have sensible defaults.

    API Endpoints

    Status: Fully backward compatible.

    All original endpoints work as before. New endpoints (/health, /metrics) are additions and don't affect existing functionality.

    Behavior Changes

    1. Error Responses:
    2. Error responses now include JSON format with request ID
    3. Plain text format still supported for backward compatibility

    4. More detailed error messages

    5. Logging:

    6. Enhanced logging format
    7. Request ID tracking

    8. Better error context

    9. Security:

    10. compat preserves historical defaults
    11. secure enables POST-only handling, strict argument checks, rate limiting, request IDs, and audit logging, and requires a command allowlist
    12. Enhanced validation
    13. Better error handling

    Configuration Migration

    Adding Security Parameters

    Before: 

    webhook -hooks hooks.json

    After (Recommended): 

    webhook \
  -allowed-command-paths="/usr/bin,/opt/scripts" \
  -strict-mode \
  -max-arg-length=1048576 \
  -max-total-args-length=10485760 \
  -max-args-count=1000 \
  -hooks hooks.json

    Adding Performance Parameters

    Before: 

    webhook -hooks hooks.json

    After (Optional): 

    webhook \
  -max-concurrent-hooks=20 \
  -hook-timeout-seconds=60 \
  -rate-limit-enabled \
  -rate-limit-rps=100 \
  -hooks hooks.json

    Environment Variables

    You can migrate from command-line arguments to environment variables:

    Before: 

    webhook -hooks hooks.json -verbose -port 9000

    After: 

    export HOOKS=/path/to/hooks.json
export VERBOSE=true
export PORT=9000
webhook

    Docker Migration

    Before (Original): 

    docker run -d \
  -p 9000:9000 \
  -v /path/to/hooks.json:/etc/webhook/hooks.json \
  adnanh/webhook:latest

    After (This Fork): 

    docker run -d \
  -p 9000:9000 \
  -v /path/to/hooks.json:/etc/webhook/hooks.json \
  -e ALLOWED_COMMAND_PATHS="/usr/bin,/opt/scripts" \
  -e STRICT_MODE=true \
  soulteary/webhook:latest

    Observability and Compliance

    This fork also supports:

    • Distributed tracing (OpenTelemetry/OTLP): Export traces to any OTLP-compatible backend. Use -tracing-enabled, -otlp-endpoint, and -tracing-service-name.
    • Audit logging: Record hook executions and requests to file, Redis, or database. Use -audit-enabled, -audit-storage-type, -audit-file-path, and related options.
    • Redis-based distributed rate limiting: Share rate-limit state across multiple webhook instances. Use -redis-enabled, -redis-addr, -rate-limit-window, and related options.

    For full parameter lists and environment variables, see Webhook Parameters.

    Rollback Procedure

    If you need to rollback:

    1. Stop Current Service: 

      sudo systemctl stop webhook
# or
docker stop webhook-container

    2. Restore Backup: 

      # Restore binary
sudo cp /usr/local/bin/webhook.backup /usr/local/bin/webhook

# Restore configuration (if changed)
cp hooks.json.backup hooks.json

    3. Restart Service: 

      sudo systemctl start webhook
# or
docker start webhook-container

    4. Verify: 

      curl http://localhost:9000/health

    1. Check Documentation:
    2. Troubleshooting Guide

    5. Review Logs: 

      # Enable verbose logging
webhook -hooks hooks.json -verbose

# Check for errors
grep -i error /var/log/webhook.log

      webhook -validate-config -hooks hooks.json

    7. Report Issues:

    8. Include version information
    9. Provide configuration (sanitized)
    10. Include relevant logs
