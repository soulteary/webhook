    迁移指南

    本指南帮助您从 Webhook 的先前版本或原始 webhook 项目迁移到此 fork。

    1. 从原始 Webhook 迁移
    2. 版本间升级

    从原始 Webhook 迁移

    此 fork (soulteary/webhook) 基于原始 webhook 项目 (adnanh/webhook)，在安全性、性能和功能方面有显著改进。

    主要差异

    1. 安全增强:
    2. 命令路径白名单
    3. 参数验证和限制
    4. 严格模式防止命令注入

    5. 改进的日志记录和脱敏

    6. 性能改进:

    7. 更好的并发控制
    8. 可配置的超时
    9. 速率限制支持

    10. 优化的请求处理

    11. 新功能:

    12. Prometheus 指标端点
    13. 健康检查端点
    14. 增强的错误处理

    15. 更好的日志记录和调试

    16. 配置兼容性:

    17. 兼容原始 Hook 配置是持续维护目标，但不代表跨 Major Version 的无条件保证
    18. 提供额外的安全和性能参数
    19. 默认 compat Profile 保持历史运行时默认行为；secure 是显式启用的更严格模式

    兼容性契约

    项目会测试 Hook JSON/YAML 兼容性，并将回归视为缺陷。但 Major Version 仍可能调整运行时行为、HTTP 错误契约、CLI 参数、默认值和 Release 资产命名。升级时应阅读跨越版本的全部 Release Notes，并在预发布环境校验；不能仅凭 Hook Schema 兼容就判断升级无风险。

    迁移步骤

    1. 备份当前配置: 

      cp hooks.json hooks.json.backup
cp /path/to/webhook /path/to/webhook.backup

    2. 下载新版本: 

      # 下载带版本号的 Release 压缩包
VERSION=7.3.0
wget "https://github.com/soulteary/webhook/releases/download/${VERSION}/webhook_${VERSION}_linux_amd64.tar.gz"
tar -xzf "webhook_${VERSION}_linux_amd64.tar.gz"

# 或使用 Docker
docker pull soulteary/webhook:latest

    3. 测试配置: 

      # 验证配置
./webhook -validate-config -hooks hooks.json

    4. 逐步迁移:

    5. 从测试环境开始
    6. 如果可能，并行运行两个版本
    7. 监控问题

    8. 逐步迁移生产环境

    9. 更新配置（可选）:

    10. 添加安全参数（推荐）
    11. 配置速率限制
    12. 设置监控端点

    推荐的安全更新

    迁移后，增强安全性：

    # 添加命令路径白名单
webhook \
  -allowed-command-paths="/usr/bin,/opt/scripts" \
  -strict-mode \
  -hooks hooks.json

# 或通过环境变量
export ALLOWED_COMMAND_PATHS="/usr/bin,/opt/scripts"
export STRICT_MODE=true
webhook -hooks hooks.json

    版本间升级

    一般升级流程

    1. 审查发布说明:
    2. 检查破坏性更改
    3. 审查新功能

    4. 注意已弃用的功能

    5. 备份: 

      # 备份配置
cp hooks.json hooks.json.backup

# 备份二进制文件
cp /usr/local/bin/webhook /usr/local/bin/webhook.backup

    6. 在预发布环境测试:

    7. 将新版本部署到预发布环境
    8. 运行完整测试套件

    9. 验证所有 hook 正常工作

    10. 更新: 

      # 下载新版本
VERSION=X.X.X
wget "https://github.com/soulteary/webhook/releases/download/${VERSION}/webhook_${VERSION}_linux_amd64.tar.gz"
tar -xzf "webhook_${VERSION}_linux_amd64.tar.gz"

# 替换二进制文件
sudo install -m 0755 webhook /usr/local/bin/webhook

    11. 重启服务: 

      # systemd
sudo systemctl restart webhook

# Docker
docker restart webhook-container

    12. 验证: 

      # 检查版本
webhook -version

# 检查健康状态
curl http://localhost:9000/health

# 测试 hook
curl http://localhost:9000/hooks/test-hook

    特定版本升级

    升级到 3.6.x

    新功能: - Prometheus 指标端点 - 健康检查端点 - 增强的错误响应 - 改进的日志记录

    配置更改: - 无破坏性更改 - 可选：添加安全参数 - 可选：配置速率限制

    迁移: 

    # 无需配置更改
# 可选：添加安全设置
webhook \
  -allowed-command-paths="/usr/bin,/opt/scripts" \
  -strict-mode \
  -hooks hooks.json

    升级到 3.5.x

    新功能: - 速率限制支持 - 增强的超时配置 - 改进的并发控制

    配置更改: - 速率限制的新可选参数 - 新的超时参数

    迁移: 

    # 现有配置按原样工作
# 可选：启用速率限制
webhook \
  -rate-limit-enabled \
  -rate-limit-rps=100 \
  -rate-limit-burst=20 \
  -hooks hooks.json

    破坏性更改

    配置文件格式

    状态: Hook 配置兼容是项目目标，但不能代替对 Major Version 变化的审查。

    现有 adnanh/webhook 配置在 compat Profile 下通常可以直接通过校验。升级生产环境前，仍应对准确配置执行校验，并测试触发、拒绝和错误路径。

    命令行参数

    状态: 向后兼容，有新增。

    所有原始命令行参数都受支持。新参数是可选的，具有合理的默认值。

    API 端点

    状态: 完全向后兼容。

    所有原始端点按以前的方式工作。新端点（/health、/metrics）是新增的，不影响现有功能。

    行为更改

    1. 错误响应:
    2. 错误响应现在包括带请求 ID 的 JSON 格式
    3. 仍支持纯文本格式以保持向后兼容

    4. 更详细的错误消息

    5. 日志记录:

    6. 增强的日志格式
    7. 请求 ID 跟踪

    8. 更好的错误上下文

    9. 安全性:

    10. compat 保持历史默认行为
    11. secure 默认启用仅 POST、严格参数检查、限流、请求 ID 与审计日志，并要求命令白名单
    12. 增强的验证
    13. 更好的错误处理

    配置迁移

    添加安全参数

    之前: 

    webhook -hooks hooks.json

    之后（推荐）: 

    webhook \
  -allowed-command-paths="/usr/bin,/opt/scripts" \
  -strict-mode \
  -max-arg-length=1048576 \
  -max-total-args-length=10485760 \
  -max-args-count=1000 \
  -hooks hooks.json

    添加性能参数

    之前: 

    webhook -hooks hooks.json

    之后（可选）: 

    webhook \
  -max-concurrent-hooks=20 \
  -hook-timeout-seconds=60 \
  -rate-limit-enabled \
  -rate-limit-rps=100 \
  -hooks hooks.json

    环境变量

    您可以从命令行参数迁移到环境变量：

    之前: 

    webhook -hooks hooks.json -verbose -port 9000

    之后: 

    export HOOKS=/path/to/hooks.json
export VERBOSE=true
export PORT=9000
webhook

    Docker 迁移

    之前（原始）: 

    docker run -d \
  -p 9000:9000 \
  -v /path/to/hooks.json:/etc/webhook/hooks.json \
  adnanh/webhook:latest

    之后（此 Fork）: 

    docker run -d \
  -p 9000:9000 \
  -v /path/to/hooks.json:/etc/webhook/hooks.json \
  -e ALLOWED_COMMAND_PATHS="/usr/bin,/opt/scripts" \
  -e STRICT_MODE=true \
  soulteary/webhook:latest

    功能添加

    新端点

    1. 健康检查: 

      curl http://localhost:9000/health
# 响应: {"status":"ok"}

    2. 指标: 

      curl http://localhost:9000/metrics
# Prometheus 格式指标

    新配置选项

    1. 安全:
    2. -allowed-command-paths
    3. -strict-mode
    4. -max-arg-length
    5. -max-total-args-length

    6. -max-args-count

    7. 性能:

    8. -rate-limit-enabled
    9. -rate-limit-rps
    10. -rate-limit-burst
    11. -max-concurrent-hooks
    12. -hook-timeout-seconds

    13. -hook-execution-timeout

    14. HTTP 服务器:

    15. -read-header-timeout-seconds
    16. -read-timeout-seconds
    17. -write-timeout-seconds
    18. -idle-timeout-seconds
    19. -max-header-bytes

    增强功能

    1. 错误处理:
    2. JSON 错误响应
    3. 请求 ID 跟踪

    4. 更好的错误上下文

    5. 日志记录:

    6. 结构化日志
    7. 请求 ID 关联

    8. 增强的调试输出

    9. 监控:

    10. Prometheus 指标

    可观测与合规

    本 fork 还支持：

    • 分布式追踪（OpenTelemetry/OTLP）： 将追踪数据导出到任意兼容 OTLP 的后端。使用 -tracing-enabled、-otlp-endpoint、-tracing-service-name。
    • 审计日志： 将 hook 执行与请求记录到 file、Redis 或 database。使用 -audit-enabled、-audit-storage-type、-audit-file-path 及相关选项。
    • 基于 Redis 的分布式限流： 在多实例间共享限流状态。使用 -redis-enabled、-redis-addr、-rate-limit-window 及相关选项。

    完整参数与环境变量说明见 配置参数。

    回滚程序

    如果需要回滚：

    1. 停止当前服务: 

      sudo systemctl stop webhook
# 或
docker stop webhook-container

    2. 恢复备份: 

      # 恢复二进制文件
sudo cp /usr/local/bin/webhook.backup /usr/local/bin/webhook

# 恢复配置（如果已更改）
cp hooks.json.backup hooks.json

    3. 重启服务: 

      sudo systemctl start webhook
# 或
docker start webhook-container

    4. 验证: 

      curl http://localhost:9000/health
